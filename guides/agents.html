Run Claude Code or Codex from your phone

The agent runs on your own machine inside tmux or herdr. Your phone attaches over SSH and steers it - switch windows, focus panes, dictate, send an image - all from the Command Dial, so most of a check-in never touches the on-screen keyboard.

What you're building

A long-lived coding agent - Claude Code, Codex, or anything else - kept alive on a machine you control inside a multiplexer. Your phone is a client, not the computer. When it sleeps or the network changes, the agent keeps working on the host and you rejoin it.

  1. Keep the agent in a multiplexer

    A bare SSH session plus an agent process dies with the connection. A multiplexer - tmux or herdr, both of which keep a session alive on the host - is the persistence boundary, so start the agent inside it, not in a throwaway login shell. In TermHub you pick Tmux or Herdr as the host's Startup mode; here's the host side:

    tmux new -A -s agent
# or
herdr --session agent
# start Claude Code, Codex, or Pi inside that session, then detach

  2. Reach the machine privately

    Prefer a private mesh over opening sshd to the internet. The Tailscale guide covers reachability with no port forwarding.

  3. Attach from the phone

    Save the host once and set its startup to attach your tmux or herdr session by name. Connecting lands you inside the existing session, not a fresh empty shell.

  4. Steer it from the Command Dial

    Open the dial and its multiplexer panel gives you window switching, directional pane focus, split, and close - plus voice and Send Image - so switching windows or focusing a pane never needs the keyboard.

Why your commands don't land in the agent's input

If you typed tmux next-window into the pane while the agent held it, those bytes would become the agent's input, not a tmux command - corrupting the foreground program. TermHub avoids this: the dial's multiplexer actions run on a separate SSH channel against the session, so they fire no matter what holds the pane. It even auto-detects your host's real tmux config.

Send an image to the agent

When the agent needs a screenshot, the dial's Send Image uploads the photo over the live SFTP connection and drops the remote file path onto the input line - so the agent reads a path on your own host, with no third-party image host.

Claude Code, Codex, Pi - or anything else

TermHub doesn't care which CLI is in the pane. The setup is identical - only the process changes. Attach to the same session and the same dial controls drive Claude Code, Codex, Pi, OpenCode, or a plain shell; it is a real PTY, so any CLI or TUI behaves the same.

What this setup won't do

  • No push when the agent finishes while the app is closed.
  • SSH transport - a dropped connection is reconnect-and-reattach (lossless with a multiplexer), not Mosh roaming.
